date: 2026-10-22
summary: Your agents keep their own MCP servers beside your integrations, notes that always open, and clean typing in Codex.
---

- **Your agents keep their own MCP servers.** Integrations are the servers
  you want everywhere; everything an agent loads by itself now loads beside
  them in a Storm session:
  - **Claude Code**: the servers you add with `claude mcp add`, its
    plugins', and a project's `.mcp.json` (after Claude Code asks you).
  - **Codex**: your servers, plugins and ChatGPT apps. Storm no longer
    rewrites them away, and Codex asks its own question before trusting a
    workspace's `.codex/` settings, instead of opening on *Folder access*
    every time. Storm's own hook is recorded as trusted, so Codex reviews
    every other hook itself.
  - **OpenCode**: your global config and its servers. A repository's own
    OpenCode config stays off: it could turn off the question OpenCode asks
    before each Storm tool.
  - If one of your servers has the same name as an integration, Storm's
    copy is renamed `storm_<name>` so both load.
  - A host that runs code you don't trust can give its sessions Storm's
    servers alone: `agent_mcp = "storm-only"` in its `runtime.toml`.
- **Notes always open.** A note the app hadn't cached could say *That note
  no longer exists* when a relay request merely dropped; now only the server
  saying so shows that, and anything else offers **Retry**. Opening a second
  note while the first loads no longer shows the first.
- **Typing in Codex is clean.** A Mac host sent keystrokes one byte at a
  time, so an arrow key could arrive as Esc and then text, and reopening a
  session answered the terminal's old questions again into the agent. Both
  are fixed.
- **Integrations** and **Claude login** in Settings are marked **Beta**.

Upgrade storm-server, storm-runtime on every host, and the apps.
