date: 2026-10-22
summary: Codex sessions on your Runtime Hosts, your agents' plugins working in Storm sessions, and signing in to a service with your own app.
---

- **Codex runs on your Runtime Hosts**, with your notes, your integrations
  and Resume, like Claude Code. Log it in once on each host (see
  [Runtime Hosts](/docs/agents/hosts/)): Storm keeps Codex's login and
  conversations in its own Codex home, so each session gets only the servers
  Storm gives it. Each launch opens on Codex's *Folder access* screen; choose
  **Open restricted**. Codex runs without its own sandbox, which needs
  something the host's service forbids, and asks before every Storm tool.
- **Cursor and Command Code can be started from the app** as terminals. They
  get no notes or integrations yet: Storm hasn't been able to check them with
  a signed-in account.
- **Your agents' plugins work in Storm sessions.** A plugin's local MCP
  server runs in the session as it would outside Storm, in Claude Code and
  Codex. A plugin's remote server (Slack's, for example) reaches a session
  only as an integration, so it is never signed in on a host. Storm now lists
  those under **Settings › Integrations › From your plugins**. Whatever a
  session leaves out is named when it starts and in the session's
  **Details**. A host can turn plugin servers off with `plugin_mcp = "off"`
  in `runtime.toml`. See [Plugins](/docs/agents/plugins/).
- **A Codex plugin that has hooks is turned off** in Storm sessions, and
  so are ChatGPT apps.
- **Sign in to a service with your own app.** For a service that won't let
  Storm register itself, such as Slack, choose **⋯ › Use your own app** on
  the integration (or Storm asks for one): paste the app's client ID and
  secret. The secret is stored encrypted on your server. Storm also
  registers with services that only accept apps holding a secret, and asks
  for the scopes a service publishes for MCP when you leave them empty.

Upgrade storm-server, storm-runtime on every host, and the apps.
