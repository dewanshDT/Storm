date: 2026-11-21
summary: An inbox for what your agents are doing — desktop, web and terminal notifications, a `notify` tool, and mark-as-unread — in-app feedback reports, and Storm's first latest-channel release.
channel: latest
---

- **Notifications (decision 161).** Storm now notices things on your
  behalf and tells you, wherever you're looking.
  - **An inbox.** The bell opens it: **Today**/**Yesterday**/**Earlier**,
    an **All**/**Unread** filter, consecutive updates from one session
    folded into a single expandable row, and a coloured icon per kind —
    needs you, finished, error, a delete request, host offline, an agent
    message, a terminal notice, or a summary after quiet hours or a
    pause. Mark one notice (or all of them) read, mark a read one unread
    again, mute a session for an hour or until it ends, or clear the
    inbox. Read state syncs across every device.
  - **A `notify` tool for agents.** An agent can call `notify` (and
    `cancel_notify`) to ask you something or tell you it's done, on any
    session whose owner has switched on **Notifies you** — in the
    launcher or Session Details, any time, even mid-session.
  - **Terminal notices.** An agent's own terminal bell (OSC 9, 777 or 99)
    becomes a notice too, under the same switch and limits; Storm answers
    nothing on the terminal's behalf.
  - **Desktop notifications.** On macOS, Windows and Linux, a notice
    becomes a real OS notification when its session isn't the one you're
    actively looking at, and an in-app toast when it is. **Settings ›
    Notifications › This device** turns it on or off, sets how much a
    notification shows (the full text, just the session, or just
    "Storm"), and, on macOS, can keep Storm running after you close its
    window so notices keep arriving.
  - **Web notifications.** On an HTTPS origin, the same **This device**
    section gets an **Enable notifications** button that asks your
    browser once you click it; over plain HTTP (a LAN box, say) it says
    "Notifications need HTTPS" instead, since browsers won't allow them
    otherwise.
  - **Settings › Notifications** also holds quiet hours, a pause, and
    per-kind mutes, synced to your account.
- **In-app feedback: Report a problem (decision 162).** **⌘K**, **Settings
  › About & health**, or **Report this** on an error snackbar all open a
  sheet that previews exactly what would be sent — your words, a kind
  (Bug/Idea/Other), an automatic screenshot you can remove, and, with
  **Include diagnostics** on, redacted server and host logs and state —
  before you press Send. **See what's sent** shows the exact bytes a send
  forwards. **Settings › About & health › Send problem reports** turns it
  off entirely. A report reaches the project only after your own server
  has it and can send it; it is queued durably and retried for up to 7
  days if your server can't reach the intake right away.
- **Release channels: stable and latest.** Storm now ships two lines
  (decision 163). **Stable** (`vX.Y.z`, off `main`, GitHub's "Latest"
  release) is what you already had. **Latest** (`vX.Y.0+`, off `staging`,
  a GitHub pre-release) carries what's merged since the last stable cut,
  for whoever wants it sooner and accepts the odd rough edge. Switch with
  `--channel latest` on `install.sh`/`install.ps1`, suite `latest` on
  apt, or `brew install dewanshdt/storm/storm-runtime-latest` on a Mac
  Runtime Host (it conflicts with `storm-runtime` — pick one line).
  Re-running `upgrade` with no channel flag always stays on whichever
  line is already installed. **v0.19.0 is Storm's first latest-channel
  release.**
- **Fixes:**
  - a hidden terminal catches up its light/dark theme the moment you show
    it again, instead of waiting for its own program to ask (157h);
  - notifications and session views no longer lag behind on a busy
    server: a notifier tick only costs what your live sessions do, not
    every session the server has ever run, and a session view no longer
    queues behind someone else's sign-in checking their password;
  - a terminal notice queued right as a session exits now always lands in
    that session's end report, instead of occasionally being swept into
    an interim post that got there first (#446);
  - Android builds on AGP 9.5.1 and Gradle 9.6.1, ahead of the floor
    notifications' own dependencies need.

Upgrade storm-server, storm-runtime on every host, and the apps. `agent.db`
gains new tables for the inbox, your notification prefs and mutes, and the
`notify` tool's buckets, pending sends and roll-ups; `auth.db` gains
`device_notification_prefs`. All additive (`CREATE TABLE IF NOT EXISTS`),
nothing migrated. The server also starts a small `feedback.db` of its own,
new and empty until you send your first report. `gateway.db` and each
vault's `index.db` are unchanged. The new stream frames and fields are all
additive, so a v0.18.0 host, server or app keeps working against a newer
one either way.
