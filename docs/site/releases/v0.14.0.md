---
date: 2026-11-01
summary: Install agents from Settings, group sessions into crews, pick a model and permission mode at launch, a Trash for every vault, agent deletes that wait for your Approve, and experimental agent spawning on isolated hosts.
---

- **Install agents from Settings › Agents** (beta). Every agent on every
  host is listed with its version and who installed it, and Claude Code,
  OpenCode, Codex, Cursor and Command Code can be installed, updated and
  removed on a Linux or macOS host, with no sudo and no terminal:
  - the host installs into its own folder, first on its search path, so a
    CLI you installed yourself keeps working and Storm only touches its own
    copies;
  - downloads come from each vendor's release channel and are checked
    against the vendor's published checksum (Cursor publishes none, and its
    row says so); Codex and Command Code need Node.js on the host;
  - once a day the host updates what it installed while none of that
    agent's sessions is running. `agent_install = "off"` or
    `agent_updates = "manual"` in a host's `runtime.toml` turns this off.
- **Crews and roles.** Group sessions that work toward one goal into a
  named, coloured crew: drag one session onto another, multi-select and
  **Make crew**, or pick a crew in the launcher. A crew's page shows its
  members, hosts, starting notes and everything they wrote, and **End all
  running** lists what it will stop first. A **role** is a label from a note
  in your Kit that the agent reads at launch. Both only organise the Agents
  page; neither changes what a session can do.
- **More at launch.** The launcher now takes a **Model** (Claude Code,
  OpenCode, Codex) and a **Permission mode**: **Manual** (the default),
  **Accept edits**, or **Auto** where the agent supports it. No option turns
  the agent's prompts off. **Tab and Shift+Tab** now reach the agent in the
  terminal (Escape, then Tab, moves focus out). Auto stays out of
  Shift+Tab's cycle unless you launched in it; a Claude Code session can ask
  for it, and a card shows its reason with **Approve Auto** or **Deny**.
- **New workspace…** at the end of the launcher's workspace list makes an
  empty folder on the host, optionally a git repository, and any number of
  sessions may now share one workspace. Needs the new storm-runtime.
- **Agents can delete, with your Approve.** An agent that may write to a
  vault can ask to delete a note or a folder there, with a reason. Nothing
  goes until you answer: a dialog opens on every device you're signed in on.
  **Approve** moves it to the Trash, **Decline** tells the agent no, and
  **Later** (or closing the dialog) keeps it waiting; the session shows
  **Needs you** until then. There is no "always allow", Auto doesn't skip
  it, and unanswered requests expire after 10 minutes.
- **Trash.** Nothing you delete is gone at once. A deleted note or folder,
  from the app, an MCP key or an approved agent, moves to the vault's
  `.trash/` with its id and history (a note removed outside Storm lands
  there as the last version the server had), and shows under
  **Trash** in the sidebar. **Restore** puts it back (never over something
  new), **Delete forever** and **Empty trash** ask first, and items go after
  **30 days** (7, 30, 90 or never, per vault). Deleting a folder with notes
  in it now asks first. Backups carry the Trash.
- **Agent spawning, experimental and off by default.** A Claude Code,
  OpenCode or Codex session can be launched with **Allow this session to
  start agents**, and then starts, messages and ends agents of its own,
  which work like Claude Code's sub-agents:
  - a child can run a different agent from its parent (Claude Code or
    OpenCode; Codex is never a child), with a name, model and role, in its
    own copy of the workspace. Once it ends, its **Work** tab shows what it
    did, and **Apply** makes that a new branch beside yours (uncommitted
    work included) or, outside git, a new folder you name;
  - children never ask you anything: what their permission mode doesn't
    cover is refused, and the refusal goes to the session that started
    them. A child's mode is never looser than its parent's;
  - children report back through a durable event queue, the parent reads
    what a child said with `read_output`, a crew holds the whole tree, and ending a session ends what it started; at most 3 live
    children per session, and no grandchildren.

  **It is offered only on a Linux host with per-session isolation turned on
  and verified**, and that isolation ships **disabled**: the
  `storm-runtime-isolation` root helper in storm-runtime's package is
  experimental, and the docs still say to leave it off. Until a host turns it
  on, no spawning tool, toggle or view appears anywhere. This release makes
  isolation run on real hosts (Storm's own AppArmor profile for `pasta`, a
  private `/dev/shm` per session) and starts isolated Claude Code with no
  theme or trust screens.
- **Session identity on Linux.** A host now checks that every connection to
  a session's Storm tools comes from inside that session, and refuses and
  logs anything else. A host that can't check (macOS, Windows, or a Linux
  host missing a precondition) says so on its row and in each session's
  Details; every tool keeps working there.
- **Fixes:**
  - after switching vaults, notes of the new vault no longer say *That note
    no longer exists* (every release since v0.9.0 had this);
  - capital letters type correctly in the terminal;
  - a new note's name can carry folders: `Ideas/Plan`, or `/Ideas/Plan`
    from the top of the vault;
  - Codex, Cursor and Command Code get their own marks;
  - Codex's login is documented from a Shell session on the host.

Upgrade storm-server, storm-runtime on every host, and the apps; storm-relay
is unchanged. The server adds tables to each vault's `index.db` (the Trash)
and to `agent.db` and `gateway.db`, all on its own at first start, with no
step for you. These changes only add, and `auth.db` is unchanged, so
v0.13.0 can still open the state, though going back hasn't been tried end
to end. It shows nothing from the Trash or the new agent features: trashed
notes stay in each vault's `.trash/` folder until you move them back.
