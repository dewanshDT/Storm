---
date: 2026-11-10
summary: Run a Runtime Host as yourself on Linux, macOS and Windows, agent spawning on every host and on by default in the launcher, per-host limits, and permission modes that are the agent's own.
---

- **Run a host as yourself.** A Runtime Host now runs one of two ways on
  every platform: **as yourself**, with no root or administrator, or **as
  a service** under its own account, as before. A host you run uses your
  own CLIs, logins and folders, and its agents can do whatever you can.
  Storm adds no sandbox of its own; each agent's own prompts and sandbox
  apply as you set them up.
  - **Linux:** `storm-runtime install --user` writes a `systemd --user`
    unit and turns on linger so the host starts at boot without a login.
    If that needs an administrator, it prints the one `sudo loginctl
    enable-linger` command instead and runs no sudo itself. Any Linux with
    systemd can use the new `storm-runtime-<version>-x86_64-linux.tar.gz`;
    the `.deb` stays the service.
  - **macOS:** a LaunchAgent, which runs while you are logged in. `brew
    services start storm-runtime` works too (never with `sudo`).
  - **Windows:** a logon task you register yourself, which runs while you
    are logged on, with no window.
  - `uninstall --user` removes it again, and `--purge` also removes its
    state and config but keeps every workspace.
- **The installer installs a new host as you.** `install.sh --runtime` and
  `install.ps1 -Runtime` now install the host as yourself. `--service`
  (`-Service`) installs the service instead, and an interactive run asks.
  The service stays the default in a few cases: a host already installed
  as the service keeps that shape on every re-run, and so do root on
  Debian, an elevated PowerShell, `-Server` on Windows, and a Mac where a
  Storm server runs as you. The enroll sheet in **Settings › Hosts** lists
  the as-you commands first and the service's second.
- **Every host says who it runs as.** Its row in **Settings › Hosts**, and
  the launcher under **Host**, reads *"Runs as"* and the account (*"· each
  session isolated"* where it isolates sessions), or *"Runs as an unknown
  account"* for a host too old to say. A session's Details keeps the
  account, isolation and identity from when it started under **Ran as**,
  and older sessions read *"Not recorded"*.
- **A host you run finds what you have:**
  - `--state` and `--config` are now optional for `enroll`, `check` and
    `serve`. Off the service each OS has its own per-user paths:
    `~/.local/state/storm-runtime` and `~/.config/storm-runtime` on Linux,
    `~/Library/Application Support/StormRuntime` on a Mac, and
    `%LOCALAPPDATA%\StormRuntime` on Windows.
  - On a Mac it reads `PATH` from your login shell, so Homebrew's
    `claude` is found, and `import_env = [...]` in `runtime.toml` passes
    other variables from that shell to every session. A `systemd --user`
    unit already has your user manager's environment, and a logon task
    has yours.
  - Your own CLI now comes before Storm's managed copy, which is only the
    fallback. On the service, Storm's copy still comes first.
  - Every OS writes a new `runtime.toml` naming `<state>/workspaces` as its
    workspace root, and creates that folder.
  - Codex uses your own `~/.codex` (or `$CODEX_HOME`) and your own login,
    and Storm writes nothing there. `codex_home = "storm"` keeps Storm's
    own home, which is still the default on the service and on Windows.
    Codex conversations from Storm's home can't be resumed from yours.
- **Agent spawning on every host, on by default in the launcher.** A
  Claude Code, OpenCode or Codex session can start agents on any host that
  says which account it runs as, not only a Linux host with isolation on.
  Identity is no longer a requirement. It is still shown on the host row
  and under **Ran as**.
  - **Allow this session to start agents** now starts ticked wherever it is
    offered, and you can untick it. Only you can turn it on: an API launch
    that doesn't ask for it still gets none, and no MCP key or agent can
    switch it on. Resume keeps the session's switch.
  - On a host with isolation off a child is an ordinary session of the
    host's account, in its parent's workspace. `start_agent` can also take
    an optional `cwd`, a folder inside one of the host's workspaces. Storm
    makes no copy, worktree or sandbox for it, so there is no **Work** tab
    or **Apply**. A child's resume is refused once its folder is gone.
  - Codex can now be a child. Cursor and Command Code can't yet.
  - A host too old to say who it runs as doesn't offer spawning, and says
    to update storm-runtime.
- **Limits per host.** **Settings › Hosts › Limits** sets how many agents
  one session can have running (3 by default, up to 10), how many run in
  one tree (6, up to 24), and optionally lowers the host's concurrent
  sessions. Depth stays at one level. Lowering a limit stops nothing; it
  only refuses new starts, and each refusal names the limit. Only you can
  change them, every change is recorded on your server, and nothing is
  written to the host.
- **Permission modes are the agent's own.** Storm passes the agent's own
  permission modes through and sets none of its own:
  - **The agent's own setting** is the launcher's default. It passes no
    flag, so your own config for that agent applies. Claude Code also
    offers **Accept edits**, **Plan**, **Auto**, **Don't ask** and **Bypass
    permissions**, and OpenCode offers **Accept edits**.
  - You choose Auto in the terminal with Shift+Tab, like any other mode. A
    session's request for Auto, with its **Approve Auto** card, is retired.
  - A child runs its parent's mode, or its agent's own setting when its
    agent doesn't have that mode. It can now ask you: its prompt shows as
    **Needs you** on the child, and you answer it in the child's terminal.
- **Smaller changes:**
  - `enroll` and `check` say what is actually wrong: permission denied is
    no longer reported as "not enrolled" or "revoked". A missing key says
    so, and only the service's own state gets the `sudo -u` hint.
    Enrolling as root is refused.
  - A child gets no write vault unless you tick **The agents it starts can
    write to {vault}** at launch. Before, every child could write to its
    parent's vault. The tick is off by default.
  - The shared-workspace notice now counts by the folder on disk, so two
    workspace names for one folder both show it.
- **Docs:**
  - The hosts docs open with
    [Two ways to run it](/docs/agents/hosts/#two-ways-to-run-it).
  - The security docs have a new section,
    [Agents run as the host's account](/docs/operate/security/#agents-run-as-the-hosts-account).
  - [Moving a host to another account](/docs/agents/hosts/#moving-a-host-to-another-account)
    covers moving a host. Enroll a new host as yourself, revoke the old one,
    and disable the old service. On Linux, keep the package (no `apt
    remove`) if your own unit runs its `/usr/bin/storm-runtime`.
- **Known gaps:**
  - Codex has no prompt hook. A Codex child stopped at its own prompt looks
    idle to its parent and shows no **Needs you**, but its terminal still
    shows the prompt.
  - Cursor and Command Code can't be started as children yet.
  - On Linux, `apt upgrade` doesn't restart a user unit that runs the
    package's binary. Run `systemctl --user restart storm-runtime`.

Upgrade storm-server, storm-runtime on every host, and the apps. storm-relay
is unchanged. A host keeps the shape it has: upgrading a service host
leaves it a service, and nothing moves it to your account. A v0.14.0 host
keeps working but can't offer spawning until it is upgraded. The server
adds three tables to `agent.db` (`host_execution`, `session_ran_as`,
`host_limits`) and two columns (`session_spawn_launch.children_write`,
`session_launch.cwd`), all on its own at first start, with no step for you.
New databases no longer create the old `mode_requests` table; on an
existing one it stays in place, unused. These changes only add, and
`auth.db`, `gateway.db` and each vault's `index.db` are unchanged. v0.14.0
should still open the state, but going back hasn't been tried.
