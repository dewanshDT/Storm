---
date: 2026-11-14
summary: Faster session switching, rows and messages that follow each session within about a second, needs-you and finished from Claude Code's own status, and a ⌘K palette that searches every vault.
channel: stable
---

- **Switching sessions is faster.**
  - Sessions you viewed recently stay open in the app: up to 3 on a phone
    or the web and 6 on a desktop, for up to 30 minutes. Going back to one
    shows it at once and fetches only the output it missed.
  - Opening a session cold gets its current screen from the server instead
    of replaying up to 4 MiB of output. For a Claude Code session that is
    about 2 KB. A session on the main screen also gets its last 1,000 lines
    of history, and one whose earlier output is gone still shows "Earlier
    output is no longer retained." above it.
  - A session that has to catch up gets its output in fewer, larger pieces,
    with fewer reads on the server.
  - A session kept in the background never answers its agent's terminal,
    resizes it or takes focus. Only the one you're looking at does.
  - A session that no longer exists stops reconnecting.
- **Rows follow each session within about a second.** The server now pushes
  session changes to the app (`GET /v1/agent/events`). The Agents sidebar,
  the overview's cards and the rail's count show a session starting to wait
  for you, stopping or ending within a second or two, on every device with
  Storm in front. Before, they waited for a refresh every 15 seconds.
  - What isn't pushed is refreshed every 60 seconds: hosts, crew names,
    colours and order, and role titles. A crew's new name, colour or place
    can therefore take about a minute to reach your other devices; a session
    joining, leaving or moving in a crew takes a second or two.
  - A host now reports a change of status on time while its agent writes a
    lot of output. Before, the change could wait until the output stopped.
- **Messages when something happens elsewhere.** A short message at the
  bottom of the window, on any screen, says so once, with **Open**:
  - "*session* **needs you**" when a session starts waiting at a permission
    prompt, a question or a sign-in. A delete request keeps its own message.
  - "*session* **finished its turn**" when the agent reports its turn is
    done.
  - "*session* **hit an error**" when the agent reports an error.
  - "*session* **stopped working**" when a working session goes idle without
    finishing (you pressed Esc or Ctrl+C), or ends. An agent that doesn't
    report its own state gets this one instead of the two above.
  - The last three come only with output you haven't seen on that device.
    Nothing is said for the session you have open, for changes while Storm
    was in the background or offline, or twice for the same change on one
    device. A newer message replaces the one showing. Storm sends no system
    notifications.
- **Status from Claude Code itself.** A host now asks the agent for its own
  status (the OSC 7501 Program Status protocol, which Claude Code 2.1.295
  and later answers) and passes it to your server: working, waiting for you,
  finished its turn or hit an error. A Claude Code session waiting at a
  permission prompt now shows **Needs you** whether or not another session
  started it. Before, a top-level one read as idle.
  - **Needs you** now also covers a question and a sign-in. Rows read
    *question · 1m* or *sign in · 2m*, are outlined and are counted on the
    rail. A session whose agent reported an error reads *hit an error · 4m*.
  - Only the state and its kind reach the server. Any text the agent sends
    with it stays on the host and isn't logged.
  - It's on by default. To turn it off on a host, add `program_status =
    false` to its `runtime.toml` and restart it.
  - These sessions show what the terminal title says, as before: one whose
    agent never asks, every session on a Windows host, and a Claude Code
    session after you move its conversation to the background (← on an
    empty prompt) or resume one from another folder.
  - If a report can't be read, the session's state shows as unknown, never
    idle. After three such reports the host stops asking new sessions until
    it restarts, and they fall back to the title.
- **⌘K opens a command palette.** `⌘/Ctrl K`, `⌘/Ctrl P`, or the search field
  that's back in the middle of the bar opens one search over note titles in
  every vault, sessions, commands with their shortcuts, Settings pages,
  folders, tags and hosts. It works from every screen, with or without a
  vault open.
  - From two letters on, **In note text** lists the notes whose text
    matches, from every vault, with the matching words highlighted. It uses
    the new `GET /v1/search`; against an older server the app searches each
    vault in turn.
  - With nothing typed it shows what needs you, your recent notes and a few
    commands. `⌘/Ctrl ⇧ P` opens it on commands.
  - Prefixes search one kind of thing: `>` commands, `@` sessions, `#` tags,
    `/` folders, and `?` lists them.
  - **Enter** opens the result, **⇧ Enter** makes a note named what you
    typed, **⌘ Enter** (Ctrl Enter elsewhere) on a note opens the launcher
    with that note as context, and **Esc** clears, then closes.
  - Offline it searches the titles this device holds, and says so.
  - On a phone it opens full screen from the pill's Search button, or the
    search bubble in Agents and Settings.
  - The sidebar's *Search {vault}* field and the old search page are gone.
    An old search link opens the vault.
- **Shortcuts work on every screen**, at any window width:
  - `⌘/Ctrl N` makes a note in the open vault from anywhere, and `⌘/Ctrl \`
    shows or hides the sidebar in Agents and Settings too (wide windows).
  - In the agent terminal on macOS, `⌘K`, `⌘P`, `⌘⇧P`, `⌘[` and `⌘]` still
    reach Storm. On Windows and Linux, `Ctrl K` and `Ctrl P` stay the
    agent's; use `Ctrl ⇧ K` or `Ctrl ⇧ P` instead.
  - Phones and tablets have none.
- **Smaller changes:**
  - A child's `needs_attention`, as Storm's agent tools report it, can now
    also read `question` or `sign_in`.
- **Known gaps:**
  - Claude Code can report its turn done while a command it left running
    in the background is still going. That's why the message says
    "finished its turn".
  - Other agents don't report their own state yet. Their prompts show as
    **Needs you** only where they did before, and they get "stopped
    working" rather than "finished its turn".
  - A Windows host reads only the terminal title.
  - Nothing times out a long *working*: an agent retrying a failing
    connection reads as working, sometimes for minutes, until it reports an
    error.
- **Not yet verified on real devices.** Automated tests cover these against
  real binaries, but they haven't been checked by hand yet:
  - how fast switching is over the Cloudflare relay, on a LAN and on a phone;
  - memory on a mid-range Android phone with three sessions kept open;
  - a cold open of a real Claude Code session with more than 4 MiB of
    output, including the mouse wheel;
  - the pushed status staying connected through the Cloudflare relay for 30
    idle minutes (the app reconnects after 45 seconds of silence);
  - three web tabs connected straight to one server;
  - a full day of real use with several Claude Code sessions at once;
  - that no Claude Code background process outlives its session after ←;
  - a macOS host.

Upgrade storm-server, storm-runtime on every host, and the apps. storm-relay
is unchanged. The faster status under heavy output and the status from
Claude Code take effect only on an upgraded host; update one from **Agents
& hosts**. A host still on v0.16.0 keeps working: it sends no program
status, so its sessions read from the title as before. An older app ignores
what's new and refreshes every 15 seconds. An older storm-runtime refuses
`program_status` in `runtime.toml`, so upgrade before adding it. The server
changes no database: `agent.db`, `auth.db`, `gateway.db` and each vault's
`index.db` are as in v0.16.0, and program status is kept in memory only.
