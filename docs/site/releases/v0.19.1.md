- **Notifications on your phone (decision 161).** Until now Android only
  showed notices inside the app while it was open. Two ways to get them
  with Storm closed:
  - **Android push.** Install the free [ntfy](https://ntfy.sh) app, then
    in Storm open **Settings › Notifications › This device** and tap
    **Enable notifications**. Android asks for notification permission
    then. Notices arrive end-to-end encrypted with the app swiped away,
    grouped per session, and tapping one opens that session. The push
    service only sees the size and timing of each message.
  - **ntfy topic (any phone, including iPhone).** **Settings ›
    Notifications › ntfy** › **Generate private topic**, subscribe to it
    in the ntfy app, and tap **Test**. Storm publishes plain text; by
    default only the session name ("Storm · tidier needs you"), never what
    an agent wrote, unless you choose **Full text**.
  - On Android and iPhone, **This device** now says plainly when
    notifications only show inside the app, instead of looking switched on.
- **macOS: far fewer keychain prompts.** Storm kept three or four separate
  keychain entries, so every update asked for your password several times.
  Your credentials now live in one entry, which is asked about once after
  this update; click **Always Allow**. Storm also only writes the keychain
  when your credentials actually change.
- **Faster releases.** Platform builds now run alongside the test suite,
  so a release takes about half as long. Nothing publishes unless every
  test passes.

## Upgrading

Upgrade **storm-server**, then **storm-runtime** on every host, and the
apps. After `apt install storm-server`, restart it with
`sudo systemctl restart storm-server`; the package keeps the old version
running until you do.

On the latest channel:
`curl -fsSL https://dewanshdt.github.io/Storm/install.sh | sh -s -- upgrade --channel latest`,
`brew upgrade storm-runtime-latest`, or `apt upgrade` with the `latest` suite.

**Schema:** additive only. `auth.db` gains `push_endpoints`,
`push_deliveries` and `vapid_keypair`. `agent.db` gains the ntfy settings on
`notification_prefs` and a delivery state on `notifications`. Nothing is
migrated or rewritten, and revoking a device deletes its push registrations.
