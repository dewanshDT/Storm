# relay-conformance

A black-box conformance suite for **SRP v1** (`docs/srp-v1.md`). It knows a
relay only by its public URL: it plays the origin server and the clients over
WebSockets, and every check is tagged with the spec section it enforces, so a
failure reads as a spec violation rather than as a test name.

Any relay must pass it. Today that is `storm-relay` (`apps/relay`); the
Cloudflare Worker relay (`apps/relay-cf`, PLAN decision 108b) is the second.

Standalone crate, like every other: no workspace, and no dependency on
`apps/relay`. Linking the implementation it judges would let the two agree by
construction.

## Running it

```sh
make relay-conformance-local            # builds storm-relay, starts it, runs the suite
make relay-conformance RELAY_URL=ws://127.0.0.1:8787   # any relay already running
```

Or directly:

```sh
cd tools/relay-conformance
RELAY_URL=ws://127.0.0.1:18900 cargo run --release -- [FILTER ...]
cargo run --release -- --list           # every check, by section
```

A `FILTER` keeps the checks whose section or name contains it (`§4.1`,
`backlogged`). The process exits non-zero if any check fails.

| Variable | Meaning |
|---|---|
| `RELAY_URL` | **Required.** `ws://` or `wss://` base of a relay in **allowlist mode**, started with the fixture contract below. |
| `RELAY_TOFU_URL` | A second relay with the same knobs and **no allowlist** (trust-on-first-use). The §4.1 TOFU checks are skipped without it. |
| `RELAY_REGISTER_PATH` | Where a server opens its trunk. Default `/register` (§4.0). |
| `RELAY_CONNECT_PATH` | Prefix of the client path, `<prefix>/<server_id>`. Default `/connect` (§4.3). |
| `RELAY_FIXTURES` | The fixture directory. Default this crate's `fixtures/`. |
| `RELAY_PEER_IP` | The address the relay should see the suite connect from. When set, `relay_peer_ip` must equal it; otherwise it must only be an IP. |
| `RELAY_MULTI_IP=1` | Also connect from `127.0.0.2`, to prove the `HELLO` limit and `relay_peer_ip` are per source address. Loopback `ws://` relays only. |
| `RELAY_LATENCY=1` | Also run the decision 91 latency check (median relayed exchange under 15 ms). Off by default: a remote relay cannot promise a localhost median. |

## The fixture contract

What a relay under test must be started with. These names are the contract the
Worker relay implements; storm-relay reads them from its environment.

**Identities** (`fixtures/`, generated by `cargo run -- gen-fixtures`, and a
unit test fails if the committed files drift from that):

| File | What |
|---|---|
| `servers.json` | 48 server identities, `srv_conf_00` … `srv_conf_47`, each with its Ed25519 `seed_b64` and `pubkey_b64` (base64url, unpadded); an `intruder` key on no allowlist line; and `unlisted_server_id` (`srv_conf_unlisted`), an id on no line. |
| `allowlist` | The 48 `(server_id, pubkey)` pairs in storm-relay's allowlist format: `<server_id> <pubkey>` per line, `#` comments. |

The keys are test keys and their seeds are public. Never load this allowlist on
a relay that serves real servers.

**Mode.** `RELAY_URL` is in **allowlist mode**, loaded with `fixtures/allowlist`
(storm-relay: `STORM_RELAY_ALLOWLIST=fixtures/allowlist`). `RELAY_TOFU_URL`, if
given, is in **trust-on-first-use mode**: no allowlist (storm-relay: neither
`STORM_RELAY_ALLOWLIST` nor `STORM_RELAY_BINDINGS`). The TOFU checks register
random `server_id`s, so a TOFU relay can be reused across runs.

**Timers and limits** (`fixtures/relay.env`; the suite reads the same file to
know what to expect):

| Name | Fixture | Production | What the relay must do |
|---|---|---|---|
| `STORM_RELAY_CHALLENGE_TTL_MS` | 2000 | 30000 | A nonce is answerable for this long (§4). The handshake must stay open longer than this, or close without `REGISTERED`. |
| `STORM_RELAY_HELLO_WAIT_MS` | 1000 | 5000 | Hold a `HELLO` with no live trunk this long, then `server_unreachable` (§5). |
| `STORM_RELAY_STREAM_ACK_TIMEOUT_MS` | 1000 | 5000 | `server_timeout` for a `STREAM_OPEN` not acked in this long (§5.1). |
| `STORM_RELAY_HEARTBEAT_DEADLINE_MS` | 2000 | 45000 | A server trunk silent this long is dead (§4.2). The suite's servers `PING` every quarter of it. |
| `STORM_RELAY_SUPERSESSION_DRAIN_MS` | 1500 | 30000 | A superseded trunk's open streams get this long, then `trunk_superseded` (§4.2). |
| `STORM_RELAY_HELLO_RATE_LIMIT` | 30 | 10 | `HELLO`s per source IP per window (§6). |
| `STORM_RELAY_HELLO_RATE_WINDOW_MS` | 1000 | 60000 | The window for the above. The suite paces itself to a third of the limit, except in the check that exceeds it. |
| `STORM_RELAY_MAX_IN_FLIGHT_STREAMS` | 4 | 20 | Un-acked `STREAM_OPEN`s per client trunk (§5.1). |
| `STORM_RELAY_MAX_TOTAL_STREAMS` | 8 | 1000 | Open streams per server trunk, across all its clients (§6 "concurrent streams per `server_id`"). |
| `STORM_RELAY_MAX_CLIENT_BUFFER_BYTES` | 1048576 | 33554432 | Bytes queued toward a client that has stopped reading before its stream is ended `client_backlogged` (§5.4). |

**Paths.** `/register` and `/connect/<server_id>` (§4.0, §4.3), overridable
with the variables above. `public_address` must be
`ws(s)://…/connect/<server_id>`; the suite checks its shape, not its host.

**Frame size.** The relay must carry a single binary frame of 16 MiB, header
included, in both directions (§5.2's ceiling).

## How it runs

Checks run one at a time, each with its own fixture identity (48 of them,
reused round-robin; a check leaves no trunk behind), so nothing one check
leaves on a `server_id` — a draining trunk, a dead registration — is seen by
the next. Every frame the relay sends is checked against §3's envelope on
arrival: a text frame without `v: 1` and a `type` fails whichever check
receives it. The suite's origins `PING` every quarter of the heartbeat
deadline and answer a relay's `PING`, so any relay heartbeat scheme works. Its
clients pace their `HELLO`s to a third of the per-IP limit, except in the
checks that exceed it, which then wait two windows.

`make relay-conformance-local` runs two storm-relays (`tools/relay-conformance/local.sh`):
allowlist mode on 18900 and TOFU on 18901, with `RELAY_PEER_IP=127.0.0.1`,
the latency check on, and on Linux the `127.0.0.2` checks. A run takes about
40 s.

| §6 errors, abuse controls | `a_malformed_frame_gets_one_undetailed_protocol_error`; `a_message_from_the_wrong_party_is_a_protocol_error`; `an_open_stream_without_an_attempt_id_is_a_protocol_error`; `every_auth_failure_is_the_same_auth_failed`; `every_open_stream_is_told_trunk_lost`; `a_server_gone_is_unreachable_until_it_registers_again`; `past_the_total_cap_an_open_is_refused_by_attempt`; `hello_is_rate_limited_per_source_ip`; `the_hello_limit_is_per_source_address` (`RELAY_MULTI_IP`) |

**Readings the suite takes** where the spec implies rather than states:

- `protocol_error` is trunk-scoped and the relay then closes the connection
  (§6 "Close the connection"); its message is the same whatever the cause
  ("minimal detail").
- A client naming a `stream_id` it does not own — another client's, one never
  issued, one closed — gets `ERROR{stream_closed, stream_id}`, nothing reaches
  the origin, and the trunk stays up.
- A message type sent by the wrong party (`STREAM_ACK` from a client, `HELLO`
  from a server, any `ERROR` not from the relay) is `protocol_error`.
- The in-flight cap is per **client** trunk; the total cap per **server** trunk.
- A refused `HELLO` is a trunk-scoped `ERROR{rate_limited}`, before or after
  the relay reads the `HELLO`.
- A `HELLO` with no live trunk is held for the whole wait (≥ 80 % of it), and
  a superseded trunk's open streams get the whole drain (≥ 80 %).
- A stream-ending `ERROR` may overtake frames queued for its stream (§5.4
  rule 2), and frames of the ended stream may trail it, since discarding them
  is only a SHOULD; the checks accept both and require everything else in
  order.

## Not black-box: storm-relay only

These stay in `apps/relay/tests` and the crate's unit tests, because they need
the relay's internals or a restart:

- **Nonce bookkeeping.** `a_replayed_nonce_is_refused`,
  `a_nonce_containing_a_colon_is_never_issued` and
  `re_issuing_a_spent_nonce_does_not_resurrect_it` pin the nonce source; from
  outside, every challenge is fresh and a spent nonce is never seen again.
  `issuing_prunes_expired_challenges` and `tracked_count()` (no nonce spent on
  a refused binding) read the challenge table; this suite checks the
  observable half — no `CHALLENGE` is sent.
- **Persistence.** `a_tofu_binding_survives_a_relay_restart` and the
  bindings-file unit tests (atomic write, corrupt file stops the relay,
  un-recorded on a failed write).
- **Internal tables.** Assertions on `relay.registrations` (released before
  clients are told), the rate limiter's pruning, the byte budget's refund
  (`a_client_that_keeps_reading_receives_many_times_the_budget`), the
  writer's discard lane.
- **storm-relay choices the spec does not make.** A `HELLO` whose `server_id`
  disagrees with the path, a malformed `HTTP_REQUEST_HEAD`, a non-boolean
  `aborted`, `CLOSE` to the origin when a client trunk dies or a stream times
  out, a trunk-level `trunk_lost` to a client holding no stream, and closing
  the superseded socket after the drain.
- **TLS** (`tests/tls.rs`, decision 71): certificate load and reload, the
  handshake deadline, `relay_peer_ip` over TLS. Deployment, not protocol.
- **Vectors** (`tests/vectors.rs`): the signed bytes as pure functions.
